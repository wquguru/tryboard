# Internationalization (U-07)

Rules for code, comments and UI text. Decision record: `docs/DECISIONS.md` → "2026-10-19 国际化".

## 1. Languages
- Web UI: English (`en`, fallback), Simplified Chinese (`zh`), Japanese (`ja`), Korean (`ko`).
- Locale = `?lang=xx` (this visit) > saved choice (`localStorage['tb-lang']`) > browser languages > `en`.
- CLI (`tryboard`, `tools/*.py|sh|mjs`), Rust core, workers' raw output: **English only**.
- Firmware `printf` output under `firmware/` stays Chinese (human decision), and so do the expected strings that match it (`uart`/serial expectations in `firmware/*.json`, test fixtures). Do not translate a string that must equal firmware output.
- `docs/` stays Chinese for now (except this file).

## 2. Using `t()`
```ts
import { t } from '../i18n';            // node-run files (web/test, checks.ts) import '../i18n/index.ts'
t('Run')                                 // English source text is the key
t('GPIO{pin} toggled {n} times', { pin, n })
```
- The key is the exact English shown to English users. Write natural English, sentence case, no trailing spaces.
- Never concatenate translated fragments (`t('LED') + t(' blinked')`). One sentence = one key with `{placeholders}`.
- Avoid plural traps: prefer `Toggles: {n}` or `{n}×` over `{n} time(s)`.
- Module-level constants may call `t()` directly: the dictionary is loaded by top-level await before any importer runs, and switching language reloads the page.
- Identifiers, CSS classes, `data-*` attributes, URLs, localStorage keys, part numbers (`BME280`, `GPIO5`), units stay as-is.
- Brand: English `TryBoard`; Chinese UI may show `试板 TryBoard`. Japanese/Korean use `TryBoard`.
- Workers: `import { useWorkerLocale } from './i18n'`, the page posts `locale` and the worker awaits `useWorkerLocale(l)` before producing human text. Raw/CLI-identical text (`CheckResult.text`, trace lines) never goes through `t()`.

## 3. Dictionaries
`web/src/i18n/<zh|ja|ko>/<area>.ts`, each `const d: Dict = { 'English key': 'translation', ... }`.

| Area file | Owner (code that uses it) |
|---|---|
| `site.ts` | site group (below): `ui/`, `home/`, `licenses/`, `*.html`, root `web/src/*.ts`, plus every string the home page or sim worker reaches |
| `select.ts` | select group (below): `advisor/` strings the home page does not reach |
| `views.ts` | `views/`, `board3d.ts`, 3D / canvas labels |
| `lab.ts` | `app/` except `app/steps/` and `benchv2.tsx` |
| `steps.ts` | `app/steps/`, `app/benchv2.tsx` |
| `data.ts` | `catalog/`, `advisor/`, display fields of `firmware/levels.json`, `firmware/examples.json` |
| `checks.ts` | `checks.ts`, `verify*.ts`, `simrun.ts`, `inputlog.ts`, `ui/say.ts` |
| `static.ts` | build-time static pages only (`tools/static_shell.mjs`, `gen_licenses.mjs`, `gen_changelog.mjs`; F-12b): in no `data-i18n` group, never shipped to the browser; the generators merge it over `site.ts` (shell keys such as nav and theme labels are reused from there) and stop on a missing key. Changelog entry text lives in `web/changelog.yaml` (`title_zh`, `desc_ja`, ...) |

- zh / ja / ko must have exactly the same keys and keep every `{placeholder}` (`web/test/i18n.test.ts` enforces this).
- If the same English key is already in another area with a fitting translation, reuse it; a duplicate key in two areas is allowed (same translation) only between the app-group areas.

### Page groups (R-20)
Pages load only the dictionary groups listed in `<html data-i18n="...">`; the build preloads them for the visitor's locale in the HTML (`dictPreload` in `web/vite.config.ts`), so they download alongside the entry script.

| Group | Files | Loaded by |
|---|---|---|
| `site` | `site.ts` | every page (`index.html`, `select.html`, `app.html`) and the sim worker (`useWorkerLocale`) |
| `select` | `select.ts` | `select.html`, `app.html` |
| `app` | `app.ts` = `data`, `checks`, `views`, `lab`, `steps`, `net` | `app.html` |

- Where a new string goes: if the home page (`web/src/home/main.tsx`, its static and dynamic imports) or `worker.ts` can reach it → `site.ts`; else if the board picker (`web/src/advisor/main.tsx`) can → `select.ts`; else the owning area file in the table above.
- "Reach" means a string literal (JSX text, imported JSON, and template-literal pieces split at parentheses, e.g. `${x} (I2C SDA / SCL, shared bus)` gives `I2C SDA / SCL, shared bus`) in any module the page entry can import; `tools/i18n_reach.mjs` computes it. `web/test/i18n-groups.test.ts` fails with `page: key` when a page reaches a key outside its groups, or when groups overlap.
- Fix a failure with `node tools/i18n_regroup.mjs` (moves entries up to the lightest group that needs them, all three locales, keeps section comments); it never moves entries down. A key reaching a page only through runtime data (fetched JSON, keys built at runtime) is not seen by the scan: put it in that page's group by hand.
- `hasT()` answers for the groups the current page loaded. A new page gets its own `data-i18n` list; a page without the attribute loads every group.
- Translate for a hobbyist audience: zh matches the existing product voice (short, plain, 人话); ja uses です/ます for sentences, noun phrases for labels; ko uses 합니다/해요-neutral 합니다체 for sentences, nouns for labels. Keep technical terms (GPIO, PWM, I2C, BOM, FreeRTOS) in Latin script.

## 4. Data files
Display fields (`title`, `goal`, `pass`, `buy`, `learn`, `brief`, `about`, `tags`, part names/notes…) are stored in English; renderers wrap them with `t(field)` and the translations live in `data.ts`. Machine fields and fields matched against firmware output keep their exact value.

## 5. Comments
- English only. Explain *why*, not what.
- At most **2 consecutive comment lines** (`//`, `///`, `//!`, `#`, `/* */` lines, JSDoc lines all count). Compress when translating; drop what the code already says.
- Allowed exceptions (keep rare): license/SPDX headers, register or packet layout tables, ASCII diagrams, and a single file/module header of ≤ 6 lines that explains a non-obvious protocol or hardware behaviour.
- Keep references intact: PLAN IDs (`P1-09`, `C-01`), `DESIGN_V2 §9.2`, register names and addresses, datasheet section numbers. Docs they point to are Chinese; that is fine.
- No Chinese characters in code, comments, identifiers or CLI output. Allowed: translation dictionaries, firmware `printf` strings and expected text that must match them, Chinese test inputs that deliberately exercise CJK handling.

## 6. Check
```bash
python3 tools/lint_comments.py [paths...]   # Chinese text + comment runs > 2 lines; exit 1 on findings
cd web && node --test test/i18n.test.ts && npx tsc --noEmit
```
Allowed CJK lines carry `lint: allow-cjk`; firmware C string literals are exempt automatically.
