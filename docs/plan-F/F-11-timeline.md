## 0. 名字：叫「环境脚本」，不叫「时间轴 / 时间线」

界面上已经有两个和时间有关的东西，新功能不能撞名：

| 已有 | 是什么 | 出处 |
|---|---|---|
| 时间线 | 编辑历史：放零件、连线、改供电、每次运行各是一步，可回退（确定性重算） | DESIGN.md §3 |
| 运行记录 | 底部坞页签：本次上电以来用户做过的输入（就是输入日志 `InputLog`） | DESIGN_V2 §4 |
| **环境脚本（新）** | **事先编排**的输入：温度曲线、光照、距离、有人经过、按钮、网络抖动，按模拟时间自动施加 | 本稿 |

三者关系一句话：**环境脚本是「写好的运行记录」**。上电后它按模拟时间把事件交给 worker，施加后的事件照常进运行记录（标来源「脚本」），所以导出的输入日志 = 手动操作 + 脚本事件，一份文件 CLI 就能重放。时间线不变，「改环境脚本」本身算时间线上的一步（可撤销）。

界面用词：底部坞页签「环境脚本」、轨道、关键帧、播放头。下文「时间轴」只指这个面板里的横轴。最终名字见 §9 Q1。

## 1. 用户场景

1. **温控风扇**（DHT11 / BME280 + 继电器）：想看「室温 0–20 s 从 24 ℃ 升到 32 ℃、停 10 s、再降回 24 ℃」时继电器在哪个温度吸合、有没有来回抖（回差写没写对）。现在只能手动拖滑块，每次不一样，也没法分享。
2. **夜灯 / 自动窗帘**（光敏电阻）：「日落 → 夜里 → 日出」一条光照曲线，30 s 走完一天，看阈值和防抖。
3. **有人经过**（PIR + 超声波）：同一时刻 PIR 高 3 s、距离 200 → 60 → 200 cm，看报警逻辑是否只触发一次。
4. **弱网重连**（Wi-Fi 示例）：10 s 时切 `flaky`、20 s 时 `netfault=silent,5`、30 s 回 `normal`，看 MQTT 重连和缓存。
5. **按键序列**：BOOT 短按、长按 3 s、双击，各在固定时刻，验证状态机。
6. **老师 / 博主分享**：把一条脚本存进作品链接，学生打开后按原速看到同一个过程（F-03b），也能下载输入日志在命令行跑。

不做：任意 JS 脚本、条件触发（「温度到 30 再按键」）、随机噪声曲线（见 §9 Q6）。脚本只是「时间 → 值」，所以可复现。

## 2. 轨道、关键帧、插值

### 2.1 轨道种类（只用 `web/src/inputlog.ts` 已有的动作，CLI 不用改）

| 轨道 | 类型 | 导出动作 | 量化（编译时） | 出现条件 |
|---|---|---|---|---|
| 温度 | 连续 | `env=t,h,p` | 0.1 ℃ | 台面有温度传感器（BME280 / DHT11 / AHT20 / DS18B20…）或房间温度可见 |
| 湿度 | 连续 | 同上（合进 env） | 1 % | 有湿度传感器 |
| 气压 | 连续（默认收起） | 同上 | 1 Pa | 有 BME280 |
| 光照 | 连续 | `lux=N` | 1 lx | 有光敏电阻（F-04a） |
| 距离 | 连续 | `dist=cm` | 0.01 cm（与 `action()` 一致；可选 1 cm 减行数） | 有超声波 |
| 电位器 | 连续 | `mv<pin>=N` | 1 mV | 有电位器 / 模拟输入 |
| 人体感应 | 开关 | `pir=1/0` | — | 有 PIR |
| 按钮 | 脉冲 | `gpio<pin>=0` … `gpio<pin>=1`（按下时长） | 1 ms | 板上 BOOT（引脚按芯片，见 §7）或面包板按键 |
| 网络 | 阶跃 + 事件 | `net=normal\|weak\|flaky\|offline`、`netfault=reboot\|dns\|silent[,秒]` | — | 固件用到 Wi-Fi（运行记录里出现过网络或作品带 Wi-Fi） |
| 旋钮 / 键盘 | 事件 | `enc=±N`、`key=name,1/0` | — | 有编码器 / 板载键盘预设 |

规则：**只给台面上真有的零件出轨道**（DESIGN_V2 §4「不造假数据」）；「+ 轨道」菜单里没有的零件灰掉，title 写「台面上没有光敏电阻」。删掉零件后轨道保留但标 ⚠「零件已移除，这条轨道不会导出」。

### 2.2 关键帧与插值

- 连续轨道：关键帧 = (时间, 值)，每段的插值方式挂在**段的左端关键帧**上：`阶跃`（保持到下一帧再跳）/ `线性` / `平滑`（smoothstep，起止斜率 0）。默认线性。第一个关键帧之前取它的值；最后一个之后保持。
- 开关轨道：只有阶跃，显示成色块（高 = 有人），拖块的左右边改起止。
- 脉冲轨道（按钮）：每次按下是一个块，长度 = 按住时长（默认 150 ms，长按 3 s 用预设）。
- 事件轨道（网络故障、旋钮）：竖线 + 标签（`silent 5s`），`net` 预设画成背景色段。
- 时间：关键帧时间**吸附到整数毫秒**；编辑时还可吸附到 100 ms / 1 s 网格（按住 Alt 不吸附）。
- 长度：脚本有总时长（默认 30 s，可改；最长 600 s，见 §9 Q4），结束后所有轨道保持最后的值。

### 2.3 预设（一键生成一组关键帧）

「开空调」（温度 30 → 24 ℃，20 s 平滑）、「升温」（24 → 35 ℃）、「日落到日出」（光照 800 → 2 → 800 lx）、「有人经过」（PIR 3 s + 距离 200 → 60 → 200 cm，两条轨道一起生成）、「弱网」（`flaky` 20 s 后回 `normal`）、「断网 5 秒」（`netfault=silent,5`）、「短按 / 长按 / 双击」。预设生成的是普通关键帧，生成后可改。

### 3.1 桌面（≥ 1024，768–1023 同桌面，面板可收起）

- 轨道头：色点（轨道色）、名字、播放头处的当前值（mono）、启用开关 ◉（关掉 = 不导出不施加，灰显）、⋯（重命名单位、清空、删除轨道）。
- 加关键帧：在轨道空白处双击；或选中轨道后按 `K` 在播放头处加（取当前值）。
- 拖关键帧：横拖改时间，竖拖改值；拖时浮出提示 `12.300 s · 31.4 ℃`；Shift 锁定只改一个方向。
- 选中关键帧：底行出现精确编辑（时间、值数字输入，插值下拉）；`Delete` 删除；`⌘C / ⌘V` 复制到播放头；框选多帧整体平移。
- 撤销 / 重做：沿用顶栏撤销（每次松手算一步，进时间线）。
- 播放头：运行中跟随模拟时间（「跟随运行」开）；暂停时可拖播放头**只看值**，不倒回仿真（倒回要「重启」，见 §5）。
- 已过去的部分（播放头左边）加一层浅灰，表示「已经施加，改了要重启才生效」；改了已过去的关键帧时顶部出提示条「改动在重启后生效 · [重启]」。
- 和右栏的关系：选中温度传感器时右栏滑块上方出现小字「由环境脚本控制 · 打开」，点击切到这个页签并选中温度轨道。用户手动拖滑块时的规则见 §9 Q5。

## 4. 数据：作品状态与导出

### 4.1 脚本源格式（存进作品状态的 `tl` 字段草案）

```ts
interface ScenarioV1 {
  len: number;                 // 总时长 ms（整数）
  tracks: ScenarioTrack[];     // 顺序 = 显示顺序 = 同一时刻的施加顺序（§4.3）
}
type ScenarioTrack =
  | { k: 'temp' | 'hum' | 'press' | 'lux' | 'dist'; on?: false; kf: [tMs: number, v: number, interp?: 's' | 'l' | 'e'][] }
  | { k: 'mv'; pin: number; on?: false; kf: [number, number, ('s' | 'l' | 'e')?][] }
  | { k: 'pir'; on?: false; spans: [startMs: number, endMs: number][] }
  | { k: 'btn'; pin: number; on?: false; presses: [atMs: number, holdMs: number][] }
  | { k: 'net'; on?: false; steps: [tMs: number, preset: string][]; faults: [tMs: number, kind: string, durS?: number][] };
```
紧凑数组是为了链接短（典型 3 条轨道 × 4 帧 ≈ 200 字符 JSON，deflate 后更短）。

### 4.2 编译：脚本 → `InputEvent[]`（纯函数，可复现的关键）

新模块 `web/src/app/scenario.ts`（纯模块，无 DOM 无 i18n，和 `sharestate.ts` 一样能在 node 测试里跑）：`compileScenario(sc, room): InputEvent[]`。规则：

1. **整数毫秒**：所有 `tMs` 是整数。`inputlog.ts` 的 `sec()` 把毫秒向下取到微秒，整数毫秒正好落在切片起点，CLI 和网页在同一个 1 ms 切片施加。
2. **按变化发，不按固定频率采样**：连续轨道在 10 ms 网格上求值（实现时可调，见 §9 Q3），先按 §2.1 量化，**量化后的值和上一次发出的不同才发一行**，并且**同一轨道两行至少隔 100 ms**（关键帧时刻例外，一定发，保证拐点值准确）。24 → 32 ℃ 线性 8 s = 80 行，而不是 800 行；阶跃段只发跳变点。原型实测：只靠量化时，光照 800 → 5 lx 平滑 10 s 一条就出 795 行（1 lx 步长），整段 30 s 脚本 1500 行；加 100 ms 最小间隔后降到 320 行。面板底行常显「本次脚本 N 行」，超过约 2000 行时提示「链接放不下运行记录，会改用 .tryboard」。
3. **量化在编译时做**：发出去的数就是 `action()` 会写的字符串（例如温度 `31.4` 而不是 `31.400000001`），网页施加的值和导出行逐字节相同，`fromScript(toScriptBody(x))` 往返不变（第二步加单元测试）。
4. **env 是三元组**：温度 / 湿度 / 气压任一变化都发一整行 `env=t,h,p`；没有轨道的那一项取作品当前的房间值（`ShareEnv`，脚本开始时快照，脚本运行期间不再读滑块）。三条轨道的变化时刻取并集，同一毫秒只发一行。
5. **同一时刻的顺序**固定：按轨道顺序，轨道内按时间；按钮在同一毫秒「先按下后松开」不会出现（按住时长 ≥ 1 ms）。CLI 是稳定排序（`core/crates/cli/src/main.rs:489`），网页 worker 的 `dueList` 也按插入顺序，所以写出的顺序就是重放顺序。
6. 关掉的轨道、零件已移除的轨道不编译。
7. 编译只在主线程做一次（上电时 / 脚本改动后重启时），结果作为**已盖时间戳的事件**交给 worker，走 F-03b 已有的 `dueList`（与 `seekTo`、`loopSlice` 同一套「切片边界 ≥ at 就施加」）。**绝不用主线程定时器施加**：消息到达时间不定，会落到不同切片（DECISIONS 2026-10-20 F-03b 已否决过这条路）。

### 4.3 与输入日志的合并

- worker 里两路事件合成一个 `dueList`：脚本编译结果（上电时整批放入）+ 用户手动操作（照旧实时盖章）。同一切片里先施加脚本事件，再施加手动事件（写进实现注释；导出时按施加顺序写，CLI 稳定排序后顺序不变）。
- 运行中改了**未来**的关键帧：主线程重新编译，把 worker 里尚未施加（`tMs` > 当前模拟时间）的脚本事件整批替换；已施加的不动（要改就重启）。
- 施加过的脚本事件照常进 `InputLog.events`，多一个只在内存里的来源标记（运行记录里显示「脚本」小标签），**导出时不写来源**，行格式与现在完全相同。
- 「导出 ▾」三项：
  - 「导出输入日志」（已有，⋯ 菜单里那个）：到当前模拟时刻为止**实际施加过的**事件 = 手动 + 脚本，就是 CLI `--inputs` 文件；
  - 「导出整段脚本」：只有脚本，编译到脚本结尾（`len`），文件头注释写 `# tryboard scenario, 30.000 s` 和建议的 `--seconds 30`（`#` 行 CLI `parse_script` 和网页 `fromScript` 都跳过）；
  - 「复制脚本源 JSON」：给高级用户改了再贴回来（「⋯ → 从 JSON 导入」）。
- 指纹一致的验收（第二步）：网页跑带脚本的作品到 `endMs` → 导出输入日志 → `tryboard run <bin> --inputs <file> --seconds <endMs/1000>` → 串口逐字节一致、指纹一致；另加「只导出整段脚本 → CLI 跑 `len`」与网页「不手动操作跑到 `len`」一致。脚本加 `tools/webtest/scenario.mjs`，编译纯函数加 node 单元测试（`web/test/scenario.test.ts`）。

### 4.4 进作品状态 v1（`web/src/app/sharestate.ts`）

推荐方案（不升 `v`）：

- 新可选字段 `tl?: ScenarioV1`（脚本源，用来再编辑和继续播放）。
- `run.s` 仍是**完整**的已施加日志（手动 + 脚本，到 `endMs`）。老页面不认识 `tl` 会忽略它，但 `run.s` 已含脚本到 `endMs` 的全部效果，快进结果不变 —— 所以加 `tl` 只是可选字段，不改 `run` 的语义，不用升 `v`。
- 打开带 `tl` 的链接：`restoreShare` 照旧快进到 `endMs`（只用 `run.s`），然后把 `tl` 编译结果里 **`tMs > endMs` 的部分**放进 `dueList` 接着播；`≤ endMs` 的部分不再施加（已在 `run.s` 里，防重复）。
- 没有运行记录（`run` 缺省）只有 `tl`：上电后从 0 开始按脚本播。
- 「重启」：脚本从 t = 0 重新开始（输入日志的定义就是「上次上电以来」）。
- 链接长度：脚本源很小；`run.s` 里脚本产生的行可能多（§4.2 规则 2 已压缩）。超过 `SHARE_LINK_MAX`（8000）时现有规则丢掉 `run`、`.tryboard` 文件带完整内容；丢 `run` 时 `tl` 保留，打开的人从 0 开始按脚本播（结果仍确定，只是不含分享者的手动操作），分享面板提示「链接太长，只带了环境脚本；完整运行请下载 .tryboard」。
- 备选（见 §9 Q2）：`run.s` 只存手动事件、打开时由 `tl` 现编译补上 → 链接更短，但老页面打开会少掉脚本事件、结果不同，属于语义变化，必须升 `v: 2` 并写 `migrate`。

## 5. 与 F-03b 原速回放的关系

- 同一条路：F-03b 是「按原速重演**录下来的**输入日志」，环境脚本是「按原速施加**事先写好的**输入」。两者都在 worker 实时循环的 1 ms 切片前从同一个 `dueList` 取事件，所以快进（`seekTo`）和原速跑到同一时刻状态逐字节一致这条保证直接继承。
- 界面同步：`web/src/app/pacedui.ts` 的 `pacedMirror` 现在只把 `gpio`（按键下沉）、`env`（房间温度）、`imu`、`dist`（障碍物）同步到 3D 和面板。环境脚本播放时也要同步：第二步给它补 `lux`（台面光照 / 光敏电阻读数）、`pir`（PIR 模块灯 + 3D 里走过的人影，若有）、`net`（网络面板状态）。脚本和原速回放共用这个 mirror，不另写一套。
- 嵌入页（F-03）：有 `tl` 的作品在嵌入页**只读**显示一条细的「环境脚本」进度条（各轨道色段 + 播放头），不能编辑；「跳到结尾」照旧 = 快进（`tMs > endMs` 的脚本事件在跳到结尾后接着播）。是否要这条进度条见 §9 Q7。
- 原速回放期间用户在实验台改脚本：和 F-03b 现有规则一样不拦，但会让结果偏离快进；顶部提示「回放中改动脚本，结果会和分享者不同」。
