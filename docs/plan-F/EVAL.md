# 平台评估与下一批规划（2026-10-20）

画布（四块板：总览、维度分级、用户旅程、优化路线）：https://claude.ai/artifact/GEvggYdYqbSXkNupMWv4MW
数据来源：2026-10-20 仓库状态（accept 125 例、示例 52 个、关卡 23 个检查点、`Reviews/accept.md` all passed）。分数是评审判断，不是测量值；做完一批后按 §2 的分级重新打分。**2026-10-21 复评：3.0 → 3.4，见 §7。**

## 1. 结论

**加权总分 3.0 / 5。** 内核已经到 L4（正确性、外设深度在同类里领先），外壳停在 L2：用户在台面上做出的东西存不下、传不出去，也没法跑我们以外的固件。

| 视角 | 权重 | 得分 | 一句话 |
|---|---|---|---|
| 正确性 | 30% | 3.3 | 内核强；固件来源窄，把分数拉低了 |
| 兴趣 | 25% | 3.2 | 场景语料覆盖约 6/10；最热的 AI 语音、摄像头缺位 |
| 可玩性 | 25% | 3.1 | 关卡和模板完整；自由搭建受限 |
| 传播 | 20% | 2.3 | 没有保存，没有可复现链接，没有嵌入 |

权重是评审选的，不是用户数据算出来的；可以改，改了以后重算。

## 3. 用户旅程断点

| 步 | 用户在问 | 状态 | 断点 |
|---|---|---|---|
| 01 被吸引 | 能帮我做出视频里那个吗？ | 中 | 入口静态，打开前看不到"动"；AI 语音、摄像头作品库里没有 |
| 02 首分钟 | 不装软件真能跑？ | 强 | 手机未上真机；首屏缺"我来改一下"的钩子 |
| 03 跟着做 | 下一步干嘛？ | 强 | 第 7 关无自动验收；任务书 → 本地编译 → 拖 bin 对新人仍长 |
| 04 自己玩 | 想接别的屏 / 改灯效 | 弱 | 不能在网页改代码；常用件放不上台面；MicroPython 跑不了 |
| 05 留作品 | 做的东西能留下吗？ | 断 | 台面不能保存，刷新就没了 |
| 06 传出去 | 能发群里吗？ | 断 | 台面分享灰显；无嵌入、分享卡、画廊、回流入口 |

最该补的是 04 → 05：把"台面状态"做成能存、能导、能用链接打开的对象。最该放大的长板是确定性：同一固件 + 同一输入 = 逐字节相同，分享出去的链接打开就能复现，挑战能公平比较。

## 5. 执行规划：拆多少个 agent session

按 AGENTS.md §9：一个子代理只做一个 PLAN ID；预计 > 150 次调用就先拆；用全新 `general-purpose` + `isolation: "worktree"`，不用 fork；`model` 显式写；子代理不再派子代理；入口写到 `path:line`（派单前在主会话 grep 好，brief 照 `docs/AGENT_BRIEF.md`）。

**原估合计约 27 个子代理 session + 4 个主会话批次；调研后修订为约 28 个实现 session + 5 个主会话批次，见 §5.4。**

- 研究：6 个，其中 1 个产出给人拍板的材料。
- P0 实现：9 个。
- P1 实现：12 个。
- 主会话：每波各一个协调会话，只负责派单、合并、跑 accept、提交；两波之间由人 `/clear`。

新编号用 F 批（"留存与传播"）。人确认后再写进 PLAN.md。

### 5.5 冲突热点（派单时写进 brief）

- **i18n 分组文件**（`web/src/i18n/{zh,ja,ko}/lab.ts` 等）：每个网页 session 都会追加键。新键加在分组末尾，由主会话合并；同一波不跑 i18n 全量整理。
- **`firmware/accept.json`、`firmware/examples.json`**：同上，追加式；合并后跑一次 `tools/golden.py save`。
- **`docs/STATUS.md`、`docs/PLAN.md`**：子代理只改自己 ID 那一行。
- **`core/crates/soc/src/devices/mod.rs`**：注册行追加式。

### 5.6 仍需深度研究、暂不排实现的

- **画廊 / remix / 账号**：要后端和部署，先由 RS-6 出方案给人决定。
- **HIL 标定**：要花钱；RS-6 给板子清单和测试计划。
- **C6 与 DVP 摄像头**：C6 的 Wi-Fi 6 / 802.15.4 驱动边界、摄像头读 3D 渲染的帧率预算都没调研。RS-3 结论：保持 P2，教程榜上无 C6；P1 做完后再定是否开 RS-7。
- **S3 SIMD（PIE / EE.* 指令）**：RS-2 发现小智原版、esp-sr、esp-dsp 都依赖它；工作量大，是否单列待人定。
- **经典 ESP32 的 BLE**：RS-5 指出完全没覆盖，可能比多 IDF 更重要；需要单独调研（RS-8 候选）。
- **周期精度 / 缓存模型**：目前明确不做。只有在出现"时序敏感固件跑不对"的真实用例时才重开。
- **权重本身**：§1 的视角权重是评审判断。上线后若有真实用户数据（漏斗、分享率），应该用数据重定。
